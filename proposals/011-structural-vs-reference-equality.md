# RFC 011: Universal Structural Equality (`==`, `!=`) and Reference Equality (`===`, `!==`)

* **Status**: Proposed
* **Authors**: Antigravity & OGShawnLee
* **Date**: 2026-07-24

---

## 1. Summary
This RFC proposes standardizing **Universal Structural/Recursive Equality** (`==`, `!=`) across all compound data types in Pino (Vectors, Maps, Tuples, Structs, Tagged Unions), while introducing **Reference/Identity Equality** (`===`, `!==`) to explicitly check whether two references point to the exact same location in memory.

---

## 2. Motivation
In value-oriented programming, comparing data structures for value equality (`[1, 2, 3] == [1, 2, 3]`) is one of the most frequent operations.

Currently, primitive types evaluate value equality with `==`, but for compound types (Vectors, Maps, Structs), developers are forced to write custom helper functions or manual loop assertions when testing nested data.

Conversely, when working with mutable objects, graph nodes, or AST nodes in the Pino C compiler (such as checking if two AST nodes refer to the same instance), developers also need an unambiguous mechanism to check whether two references point to the same memory buffer (identity comparison) without triggering expensive recursive structure comparisons.

Distinguishing `==` (Structural Value Equality) from `===` (Reference Memory Equality) solves both problems cleanly, aligning Pino with modern language design standards (such as Kotlin, Swift, and JavaScript).

---

## 3. Proposed Semantics & Syntax

### 3.1 Structural Equality (`==` and `!=`)
The `==` operator performs deep, recursive structural comparison across all data types:

- **Primitives (`int`, `float`, `bool`, `rune`, `string`)**: Compares values directly.
- **Vectors (`[]T`)**: Returns `true` if both vectors are identical references (`a == b`) or if both have equal length and each corresponding element at index `i` is structurally equal (`a[i] == b[i]`).
- **Maps (`map[K, V]`)**: Returns `true` if both maps are identical references (`a == b`) or if both have equal size and for every key-value pair `(k, v)` in `a`, `b` contains key `k` with value `b[k] == v`.
- **Structs**: Returns `true` if both structs are identical references (`a == b`) or if all fields are structurally equal.
- **Tagged Unions**: Returns `true` if both instances are identical references (`a == b`) or if both have the same tag and associated payload fields are structurally equal.

> [!NOTE]
> **Note on Tuples**: Tuples (`@(T1, T2, ...)`) in Pino are exclusive constructs for multi-return values and destructuring bindings; they are not first-class dynamic heap values and thus do not participate in equality operations.

> [!TIP]
> **Performance Optimization (Identity Short-Circuiting)**: Every autogenerated `_equals` function for structural equality starts with an $O(1)$ reference check (`if (a == b) return true;`). If two variables point to the exact same location in memory, structural equality (`==`) short-circuits instantly to `true` without traversing nested elements or fields, and structural inequality (`!=`) short-circuits instantly to `false`.

#### Example:
```pino
val a = [1, 2, 3]
val b = [1, 2, 3]

assert a == b // true (equal contents)
assert a != [1, 2, 4] // true (different contents)
```

### 3.2 Reference Equality (`===` and `!==`)
The `===` (and `!==`) operator performs physical identity comparison:

- Returns `true` if and only if both operands point to the exact same memory address (e.g. `a == b` pointer comparison in transpiled C / VM stack).
- **Primitives**: `a === b` behaves identically to `a == b` for primitive stack values.
- **Heap Objects (Vectors, Maps, Structs, Unions)**: `a === b` returns `true` if `a` and `b` reference the same heap pointer, even if two distinct instances happen to contain identical data.

#### Example:
```pino
val a = [1, 2, 3]
val b = [1, 2, 3]
val c = a

assert a == b  // true  (structural equality)
assert a === b // false (different memory instances)
assert a === c // true  (same memory instance)
assert a !== b // true  (not the same reference)
```

## 4. Technical Architecture & Compiler Implementation

### 4.1 Parser (`Parser/`)
- Register `===` (`OperatorType.IdentityEqual`) and `!==` (`OperatorType.IdentityNotEqual`) in `Lexer` and precedence maps with precedence matching `==` and `!=`.

### 4.2 Static Checker (`Checker/`)
- Validate that operands of `===` and `!==` have compatible types.
- Infer return type as `bool`.

### 4.3 C Transpiler (`TranspilerC.cs`)
- **For `==`**: Emits autogenerated recursive equality functions (`Vector_T_equals(a, b)`, `map_K_V_equals(a, b)`, `Struct_equals(a, b)`, `Union_equals(a, b)`).
- **For `===`**: Emits direct pointer comparison in C: `(a == b)`.
- **For `!==`**: Emits direct pointer inequality in C: `(a != b)`.

### 4.4 Evaluator & VM (`VM/`)
- Evaluator and Bytecode VM evaluate `===` as direct reference/value equality on evaluation stack frames.
